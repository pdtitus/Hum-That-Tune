Architecture
------------
- server.js is intentionally game-agnostic. It hosts sessions, participant tokens, opaque state, and WebSocket event routing.
- The browser frontend owns BackTrack game semantics.
- Current backend sessions are in memory only. A Cloud Run restart loses active games.
- Firestore exists but is not yet used by server.js as a persistence adapter.
- The existing server protocol is documented in SERVER_PROTOCOL.md.

Current unresolved issues and next-session context
------------------------------------------------
Date: 2026-09-11
Branch: ntitus/testing_branching

1) Host team join/rejoin bug
- In the lobby team list, the host is currently treated as owner-only and does not get a visible "Join Team" button for teams he is not already in.
- This means if the host leaves a team, he has no way to rejoin it from the UI.
- Relevant code: app.js -> renderTeamList(), modifyCurrentTeamMembership(), prepareTeamEdit(), createHostTeam().
- Expected behavior: the host should be able to join a visible team in the lobby, even if he is not the owner, and should not be blocked from rejoining after leaving.

2) Non-host players cannot create teams
- The lobby currently hides the team builder for non-host players in renderLobbyState():
  - "teamBuilder.classList.toggle('hidden', !isSessionHost);"
- That prevents regular players from creating teams even though they should be allowed to participate in team formation.
- Relevant code: app.js -> renderLobbyState(), teamBuilder UI in index.html.
- Expected behavior: all players should be able to create and manage their own teams in the lobby; only the host should be allowed to press the start button and transition the room into the active game state.

3) Team matrix reset bug
- When a team is created, the song/genre difficulty matrix toggles every button, but the UI should reset to all-off before the next team creation/edit flow.
- Current symptom: the selected state persists in a way that appears to toggle all options unexpectedly rather than resetting to default empty.
- Relevant code: app.js -> getSelectedSongOptionsFromUI(), setSelectedSongOptionsInUI(), bindTeamMatrixControls(), createHostTeam().
- Expected behavior: after a team is created or saved, the matrix should return to a clean default state with all category/difficulty buttons unselected until the next interaction.

4) Non-host players remain in lobby after host starts
- The current app allows the host to start the game, but non-host participants remain in the lobby state instead of being transitioned with the room into the gameplay state.
- This looks like a deferred issue tied to the later round-turn implementation, not something to solve in the current lobby patch.
- Relevant code: app.js -> startGameFromLobby(), handleSessionMessage(), session state handling in server.js.
- Expected behavior: once the host starts the game, all remaining participants should be included in the active game state model as the game enters round 1; this will likely be handled when the round/turn engine is implemented.
