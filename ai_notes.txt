Architecture
------------
- server.js is intentionally generic and session-oriented; it owns the room, participant tokens, WebSocket routing, and state snapshots.
- app.js owns BackTrack rules and UI behavior, including team membership, active-turn sequencing, deck creation, song reveal, timer logic, scoring, and turn progression.
- teamDecks are built from each team's selected song options and should remain team-specific.
- currentTurnSequence is the authoritative order for the current round. It must follow the actual player list for each team and must not be regenerated mid-round in a way that advances players incorrectly.
- activePlayerName and currentTeamIndex must stay synchronized with the current turn, or the game looks like it advanced while the UI remains on the wrong player/team.
- currentSong is intentionally hidden from the public view except for the active player; the rest of the room stays in a shared spectator state.

Known game-flow bugs (current priority)
----------------------------------------
1) Round transition / active-player handoff bug
- In multi-player scenarios, the next turn is not always assigned to the correct player after a song is scored or passed.
- There are reports that the host did not advance correctly into round 2 when the round reached its end.
- There are reports that a second player played twice while the original active player never got a second turn in the same round.
- Relevant code: app.js -> getActiveTurn(), syncActiveTurnState(), nextButton click handler, startGameFromLobby(), showActivePlayerStartScreen().
- Expected behavior: every player in the current round should be assigned one turn before the round rotates. The next round should begin with the first player in the turn sequence again, not with a skipped or duplicated player.

2) Team rotation logic bug
- In a two-team / two-player scenario, the second team should begin after the first turn is completed and should not have both players play for both teams in the same round.
- The current logic is allowing players from the second team to be treated as if they were playing for the first team or as if the sequence was being rebuilt incorrectly mid-round.
- Relevant code: app.js -> buildTurnSequenceForTeams(), getActiveTurn(), currentTurnIndex behavior, nextButton click handler.
- Expected behavior: sequence generation should follow a stable team/player ordering for the round; a player's team must remain tied to the same team until the round sequence moves past that team’s players.

3) Pass action UI / state bug
- Team passes are currently not behaving as a visible round resource and the UI does not clearly communicate the pass allowance to each team.
- The game should give each team 2 passes per round.
- The pass button should visibly show remaining passes and disable itself when the team is out of passes.
- Relevant code: app.js -> showCurrentTeam(), passButton handler, team state initialization, resetRoundPasses().
- Expected behavior: each team starts every round with 2 passes, the UI updates the pass count immediately, and the button disables at zero, with no ability to continue pass-spamming after depletion.

4) Song-selection mismatch for non-host players
- In the multiplayer tests, non-host players are sometimes shown songs that do not match the current team selection deck.
- This likely means the deck is being rebuilt or re-synced from stale team data after the lobby/state update.
- Relevant code: app.js -> buildDeckForTeam(), applyIncomingGameState(), teamDecks assignment, revealNextSong().
- Expected behavior: each team's deck should be derived only from that team's selected options and remain stable for the duration of the turn until a new round or team assignment resets it.

5) Current loss of round-state continuity
- The app is still missing a clear and trustworthy round progression model that handles team rotation, pass resets, and next-player transitions in a single place.
- The current implementation has too much logic spread across UI handlers and state recalculations.
- Relevant code: app.js -> nextButton handler, startActiveTurn(), showActivePlayerStartScreen(), getActiveTurn(), updatePlayerView().
- Expected behavior: all round transitions should use the same canonical turn sequence and the same round reset rules, regardless of which screen or client is preparing the next state.

Important implementation details
--------------------------------
- app.js uses BACKEND_URL. For localhost it uses http://localhost:3000; otherwise it uses the deployed Cloud Run URL.
- Host sends session state updates with status, teams, currentRound, currentTeamIndex, totalRounds, and activePlayerName.
- The active player's song view is intentionally private; everyone else remains in a shared spectator view.
- Team-specific song options are normalized with helper functions like normalizeTeamOptions() and buildDeckForTeam().
- The pass rule is per team, not per player.
- A team gets 2 passes each round; passes reset at the start of a new round.
